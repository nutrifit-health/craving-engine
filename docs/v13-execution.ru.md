# V13: выполненный эксперимент и порядок воспроизведения

Статус на 17 октября 2026 года: проверки и эксперимент **выполнены по прямому запросу владельца**. 112 тестов прошли, 7 требуют недоступного внешнего материала. Результат: 65 меньше ложных и 8 больше верных предупреждений суммарно, но основной критерий не выполнен; [подробный отчёт](results-v13.ru.md). Каталоги команд ниже уже существуют и не должны перезаписываться.

Канонический проект протокола: [PRT-2026-007, версия 1](https://gov.nutrifit.health/documents/6ad2e714556a2264e7a13682/versions/1). Задача подготовки: [TASK-2026-0798](https://gov.nutrifit.health/tasks/6ad2e6c7556a2264e7a1367a).

## Зачем следующий эксперимент

V11/V12 сравнивали качество вероятностей и способы персонализации. V13 отвечает на отдельный вопрос: помогает ли резервирование ограниченных уведомлений обнаружить больше срывов, сохранив или снизив ложные тревоги? Это не новая модель риска и не исследование предотвращённых срывов.

Главный результат будущего отчёта: TP/FP/FN/TN, recall, precision, FPR и предупреждения/пользовательскую неделю для двух политик на одних событиях. Положительный итог требует ≥5 п.п. среднего прироста recall, положительного прироста на обоих dev-сидах, без роста FPR и частоты предупреждений и без снижения precision на каждом. Все эти требования применяются после лимита 2/168h.

## Что реализовано

- `research_v13/policy.py`: две политики в одном причинном механизме. Аргументы решения — только время и вероятность; метки ему недоступны. Надбавка за резервирование последнего слота уменьшается по мере приближения освобождения следующего слота.
- `research_v13/evaluation.py`: расчёт по полным ежедневным траекториям; неизвестные исходы отдельно; парные пользовательские интервалы. Политика работает и без меток, но основной эксперимент требует полной синтетической оценки.
- `research_v13/experiment.py`: `freeze` использует только dev_1 для выбора; `evaluate` применяет уже выбранные политики на dev_2/dev_3. Сохраняются хеши входов и реализации, все 88 попыток выбора и решения. Перезапись каталогов запрещена.
- `tests/test_v13_policy.py`: сценарии границы 168 часов, причинности, разных знаменателей FPR/precision, пропусков, изоляции пользователей, остановки без допустимого кандидата, раздельной заморозки и оценки, неизменности входов.

## Перед расчётами

Для повторных проверок требуется соответствующий запрос пользователя. Команды ниже показывают выполненный маршрут; не являются разрешением на новые эксперименты или подбор.

1. Сначала выполнить разрешённые проверки и исправленный replay по [порядку V12](v12-repair-replay.md). Исторические `runs/v12-stage2` и `runs/v12-closure-20261017` не перезаписывать.
2. Сохранить выводы проверок и воспроизведения. Наличие поля `status` в JSON не заменяет успешную проверку; CLI V13 отсеивает старый формат, но не подтверждает сам по себе достоверность происхождения файла.
3. Проверить V13 в рамках явно разрешённого scope. Для широкой проверки применимы весь репозиторный pytest, линтер затронутых модулей, сборка wheel/sdist и включение `research_v13` в пакет. Браузер, production и реальные push здесь не затронуты.

Пример команд из корня `apps/craving-engine` после разрешения:

```bash
NUTRIFIT_BACKEND_ROOT=/Users/gurutom/Develop/NutriFit/apps/backend V12_REPLAY_BUNDLE=runs/v12-repair-20261017/closure .venv/bin/python -m pytest tests/ research_v8/ research_v9/ research_v10/ --ignore=runs --ignore=results
.venv/bin/ruff check research_v12 research_v13 tests/test_v12_*.py tests/test_v13_policy.py

```

## Заморозка и оценка — отдельные команды

После исправленного replay V12, без повторного обучения и подбора моделей:

```bash
.venv/bin/python -m research_v13.experiment freeze \
  --stage2-dir runs/v12-repair-20261017/stage2 \
  --output-dir runs/v13-policy-20261017/freeze
```

Если `frozen_policy.json` содержит `stop_no_feasible_candidate`, завершить отрицательным поисковым результатом. Не менять сетку.

```bash
.venv/bin/python -m research_v13.experiment evaluate \
  --stage2-dir runs/v12-repair-20261017/stage2 \
  --frozen-policy runs/v13-policy-20261017/freeze/frozen_policy.json \
  --output-dir runs/v13-policy-20261017/evaluation
```

При существующем каталоге сохранить его и выяснить причину повторного запуска. Не создавать цепочку новых запусков с меняющимися настройками ради положительного результата.

## Что включить в отчёт

Источники входов и их хеши, выбранные конфигурации, полный журнал подбора, пользовательские и pooled метрики, числители и знаменатели, парные интервалы по каждому сиду, фактический лимит уведомлений, долю пропущенных исходов, статус критериев допуска. Входные вероятности V12 должны остаться неизменными.

Результат на dev_2/dev_3 остаётся **поисковым**, поскольку эти данные участвовали в V12. `eligible_for_new_confirmatory_protocol=true` означает только возможность подготовить независимое подтверждение, не успех продукта. Подтверждающие сиды V12 остаются закрытыми. Реальный сбор данных, вмешательства и следующие исследования потребуют собственных контрактов и протоколов.

Если качество не улучшилось, следующая гипотеза касается информации на входе: короткие своевременные самоотчёты и наблюдаемый контекст. Не повторять перебор архитектур при неизменных источниках данных. Научное основание и ограничения источников приведены в [протоколе](protocol-v13.ru.md).
