# Craving Engine V10 — LIF и локальная пластичность
Исследовательский протокол, 2026-10-07. Работа: [задача V10](https://gov.nutrifit.health/tasks/6ac6b3a156965bd66f60880f). Предыдущий результат: [V9](https://gov.nutrifit.health/documents/6ab46925560e2cbddbef9645). Источник идеи: [пример ToxaBes](https://habr.com/ru/articles/1045696/).

## Вопрос и область вывода
Помогают ли LIF и парная STDP, модулированная ошибкой прогноза, персональной адаптации относительно той же памяти без спайков? Отдельно проверить сам опубликованный пример. Это конечная серия синтетических экспериментов, не проверка всех SNN и не клиническая валидация. Улучшение после двух обновлений отличается от достаточного качества прогноза.

## Последовательность до результатов
1. Исполняемый аудит точного листинга автора: градиенты, изменение параметров, воспроизводимость eval, перенос traces, фактическая связность; архив URL/хеша и диагностик. Чужой листинг не включается в распространяемый код.
2. Проверка целостности замороженного V9, причинности, изоляции пользователей и observed/evaluation labels. Воспроизвести тесты и основные результаты V9 в отдельном каталоге.
3. Реализовать собственную прозрачную адаптацию механизма, не называя её копией сети автора: общая фиксированная кодировка, индивидуальный readout, LIF в 32 внутренних тактах каждого события; между событиями нейронная динамика сбрасывается. Утечка в тактах симуляции не равна забыванию опыта в календарных днях.
4. Подбор только по первой половине calibration-пользователей (10), пороги только по второй половине (10). Зафиксировать всё до чтения development-метрик. Development V9 уже известен и остаётся исследовательской выборкой.
5. Новые механистические сценарии с заранее заданными seeds: стабильность, резкая и постепенная смена зависимости, временное отклонение, шум ответов, задержка и редкие ответы. Базовая вероятность известна генератору по общим признакам; индивидуальная поправка скрыта от моделей. Это контролируемая задача персонализации, не реалистичная модель питания.
6. Зафиксированные варианты оцениваются без нового подбора; сохраняются все результаты, стоимость и память, контроль воспроизводимости и отчёт RU/EN.

## Конечная матрица
Общий GBDT p0 V9 одинаков для основных абляций. Baselines: population, scalar memory, исходная KC direct memory; отдельная реплика самостоятельного MB V9.
LIF: tau_mem 5/20/80, tau_syn 5, threshold 2.5, 32 такта. Профили (tau_mem,gain): (5,0.1),(20,0.03),(20,0.1),(20,0.3),(80,0.1). Ток масштабируется медианой положительных training KC-активаций.
Правила: direct error×rate, парная STDP без ошибки (контроль), парная STDP×prediction error (трёхфакторная инженерная гипотеза). STDP pre/post traces имеют tau=20 тактов, Aplus=1,Aminus=1.2; порядок до обновления traces исключает одновременную пару. Post-импульсы получаются детерминированным накопителем вероятности общего readout. Eligibility нормируется по L2 и сохраняется до feedback; она не вычисляется заново по изменившимся весам.
Fast learning rate: 0.2/0.8; slow=0.15×fast; прочие ограничения/забывание V9 одинаковы. Gate и familiarity остаются прежними, ungated p_learning публикуется как отдельная диагностическая политика. Выбор одного варианта каждого семейства — минимум macro Brier на tuning; равенство разрешается именем. Без дальнейшего перебора после оценки.

Дополнение до запуска: для выделения эффекта правила обучения добавляются direct и STDP-контроли с точно теми же LIF-параметрами и learning rate, что у выбранного rSTDP. Эти matched-контроли не выбираются по development. Сравнение отдельно оптимизированных семейств отвечает практическому вопросу, а matched-контраст изолирует правило.

## Новые сценарии
40 пользователей ×120 ежедневных решений, change day60. Calibration seed6101; evaluation seeds7101,7102,7103, непересекающиеся IDs. 16 наблюдаемых нормальных контекстов, ON/OFF-код с anchor (33 координаты), общий logistic p0; персональные коэффициенты и смещения не доступны модели. Stable/abrupt/gradual/transient; noisy feedback15%; delay72h вместо20h; reporting50% и10% вместо80%. Параметры моделей переносятся из V9 tuning без подбора на новых evaluation seeds. Пороги фиксируются на отдельном calibration-сценарии. Потенциально неблагоприятный перенос размерности указывается явно.

Шум, задержка и reporting накладываются на abrupt, поэтому сравниваются с abrupt. Как в V9, при совпадающем timestamp сначала рассчитывается прогноз: используются только ответы строго раньше решения. В delay72 ответ приходит через72 часа, но первый использующий его ежедневный прогноз получается через96 часов. Это правило одинаково для всех моделей.

## Метрики и критерии
Macro Brier — первичная метрика качества вероятностей; AUC, recall, FPR, J, precision, индивидуальные регрессии и уведомления при лимите2/7дней — вторичные. Парные bootstrap по пользователям, 2000 draws, seed20260923 (переиспользованный оценщик V9); для диагностических кривых адаптации seed20261007. Сохранять 95% интервалы, не считать дни независимыми. Главный причинный контраст LIF+rSTDP против LIF+direct при одинаковых параметрах; общий практический контраст против tuned non-spiking direct и scalar. Один заранее выбранный вариант каждого семейства; остальные результаты диагностические, без заявления подтверждения по множественным сравнениям.
Положительный результат требует снижения Brier с CI ниже0 и не менее0.002 абсолютного выигрыша, FPR не выше+0.01, J не ниже, без ухудшения ошибки вероятностей в стабильном сценарии более0.002. Аналогичное направление должно повториться минимум на2/3 новых seeds. Если условия не выполнены, рекомендация не подтверждена в этой реализации.
Для скорости адаптации публиковать ошибки после 0/1/2/5/10/20 реально полученных post-change исходов, отдельно gate и ungated, число пользователей и решений. Никакое снижение на1–2 примерах само по себе не означает достижения достаточного качества.
Контроли: отсутствие feedback, перемешанные feedback, временные границы, отсутствие межпользовательской утечки, сериализация, одинаковые seeds/повторные прогнозы, знак и порядок STDP, градиенты чужого листинга. Стоимость: wall time с окружением, числовые буферы и полное сериализованное состояние отдельно. Дальнейшая автоматическая оптимизация после отрицательного результата запрещена; новая гипотеза требует отдельного протокола.
