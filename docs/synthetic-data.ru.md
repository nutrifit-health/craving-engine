# Новые синтетические корпуса и место продолжения

[English](synthetic-data.md) · [Русский](synthetic-data.ru.md)

Единственное место активной разработки Craving Engine — этот самостоятельный
репозиторий. `research_v9/` и `research_v10/` сохраняют прежние эксперименты;
`synthetic_data/` содержит инструменты новых корпусов, выделенные из приватного
архива NutriFit. Перенос проверен 16 октября 2026 года при отсутствии старого архива.

## Проверки переноса

16 октября 2026 года прошли 65 Python-тестов и 31 подпроверка, включая 13 новых
случаев миграции. Семь отдельных тестов аудита авторского листинга пропущены:
для них нужен внешний прочитанный снимок исходника. Проверены повторяемость
артефактов, разделение когорт, задержка обратной связи, недоступные записи,
исключение скрытых исходов из входов, защита выходных каталогов и реальный
необязательный TS-энкодер. Существующие 29 тестов энкодера backend тоже прошли.
Пройдены Python lint и форматирование, проверка типов backend и адаптера,
а также отдельный lint адаптера. Общий lint backend также запущен: он сообщил
о 1117 ранее существовавших ошибках в 133 неизменённых файлах. Эти посторонние
файлы не исправлялись в рамках переноса.

Собраны исходный дистрибутив и wheel. Установленный wheel создал 540 строк
из временного каталога вне репозитория. Старый архив отсутствовал при всех
запусках. Это проверка инженерного переноса; обучение моделей и новая оценка
их предсказательной или клинической полезности не проводились.

Из этого репозитория, после установки тестовых зависимостей:

```sh
python -m pytest tests research_v8 research_v9 research_v10 -q -rs
ruff check synthetic_data tests
ruff format --check synthetic_data tests
python -m build --no-isolation
```

Для интеграционного теста задайте `NUTRIFIT_BACKEND_ROOT` — путь к локальному
`apps/backend`. Без него этот тест явно пропускается. В приватном checkout
из `apps/backend/scripts/craving-research`:

```sh
../../node_modules/.bin/tsc -p tsconfig.json
node ../../../../scripts/run-eslint.mjs encoder.ts types.ts --max-warnings=0
```

## Что сохранено для дальнейшей работы

- `population.py`: сеточная генерация новых профилей, без каталога уже известных персон.
- `simulator.py`: 180 дней наблюдений, пропусков, скрытых исходов и смены режима.
- `contexts.py`: учёт времени доступности записей, окон наблюдений и истории пользователя.
- `features.py`: наблюдаемые признаки, история за 7/28 дней и только поступившие ответы.
- `quality.py`: встроенная диагностика согласованности синтетических наблюдений.
- `generate.py`: создание отдельного корпуса с seed, схемами, исходниками и manifest.
- `nutrifit_encoder.py`: необязательный явный вызов локального энкодера NutriFit.

Старые модели, HTTP-сервис, исторические runners, известные диагностические персоны,
журналы и checkpoints не перенесены. Полная история остаётся в приватном Git;
[происхождение выбранных исходников](../research-migration.json) сохранено отдельно.

## Автономная генерация

Сначала установите этот Python-пакет по инструкции основного README. Следующая
команда — справочный пример, не выполненный эксперимент. Перед исследованием
зафиксируйте собственный протокол, размеры когорт и seed.

```sh
python -m synthetic_data.generate --output runs/new-corpus --seed 2026101601 --users 60 20 40
```

Команда создаёт новые training/calibration/development когорты по 180 решений
на пользователя. Каталог назначения должен отсутствовать. `data/` и `results/`
не принимаются как место новых данных. Незавершённый запуск оставляет `.incomplete`.

Выходные файлы каждой когорты:

- `*.X.npy`: текущие наблюдаемые признаки;
- `*.history.X.npy`: текущие признаки, предшествующая история и доступный feedback;
- `*.records.jsonl`: идентификаторы строк, время решений и время доступности ответов;
- `*.evaluation.jsonl`: полные синтетические исходы только для оценщика;
- `*.contexts.jsonl`: наблюдаемый контекст в том же порядке строк.

Общие `schema.json` и `manifest.json` фиксируют порядок признаков, единицы,
seeds, размер когорт, контрольные суммы и версию окружения. `sources/` сохраняет
текущие исходники генерации. Наличие outcome в records не разрешает использовать
его до feedback_at. Отсутствие ответа остаётся пропуском. Скрытые исходы и
параметры профиля не входят в X. Доли ответа 0.8/0.7 и задержка 20 часов —
сценарные предположения, а не измерения реальных пользователей.

## Необязательные признаки энкодера NutriFit

Для владельца отдельного локального checkout NutriFit:

```sh
python -m synthetic_data.generate --output runs/new-corpus-with-pn --seed 2026101601 --users 60 20 40 --backend-root /absolute/path/to/NutriFit/apps/backend
```

Нужны уже установленные зависимости backend, его локальный `tsx` и адаптер
`scripts/craving-research/encoder.ts`. Клиент не устанавливает зависимости,
не ищет соседний репозиторий и не обращается к сети/БД. TypeScript-адаптер остаётся
в приватном NutriFit рядом с его контрактами. Этот режим добавляет 16 PN-признаков;
без него схема содержит только наблюдаемые признаки. Режим и схема записываются
в manifest. Интеграционные метаданные могут содержать локальные пути: не публикуйте
новые результаты автоматически.

## Границы

Это подготовка данных для следующего исследования, не новая обученная модель,
не слепая проверка и не воспроизведение V9. Новые идентификаторы и seeds меняют
траектории. Новый корпус нельзя подставлять вместо `data/v9-frozen`;
для сравнения моделей нужен отдельно зафиксированный протокол и runner.
Генератор V10 продолжает работать со своими контролируемыми сценариями.
Синтетические формулы не доказывают медицинскую реалистичность или пользу людям.

Полный удалённый архив доступен владельцу приватного NutriFit в revision
`27d3124cb403765ae50c75d43ad1c7b5fd9b2170`, путь
`apps/backend/research/craving-engine-archive`. Его извлечение не требует
возвращать архив в активное рабочее дерево публичного проекта.
