# V13: больше обнаруженных срывов при ограниченном числе ложных тревог

Дата: 2026-10-17. Статус: проект протокола и реализация прототипа; новых результатов пока нет. Работа выполняется в [задаче подготовки V13](https://gov.nutrifit.health/tasks/6ad2e6c7556a2264e7a1367a). Предшествующие [исправления V12](https://gov.nutrifit.health/tasks/6ad2e203556a2264e7a1366c) требуют явно разрешённого воспроизведения. Исходная [программа V12](https://gov.nutrifit.health/documents/6ad2c396556a2264e7a1339e/versions/2) не переоткрывается.

## Цель и границы
Проверить, можно ли лучше выбирать моменты предупреждений на уже рассчитанных вероятностях. Меняем только политику уведомлений; GBDT, память и вероятности не обучаем заново. В приложение ничего не внедряем. Офлайн-предупреждение — метка решения, а не отправленный push и не предотвращённый срыв.

## Научные ориентиры
- Crochiere et al., 2021: 23 участника, 6 недель; EMA sensitivity 59%, specificity 72%; сенсоры 63%/60%. EMA требовала больше усилий. Это аргумент учитывать нагрузку и исследовать дополнительные контекстные сигналы, но не доказательство пользы новой политики NutriFit. [Первичная публикация](https://pubmed.ncbi.nlm.nih.gov/34529044/).
- Chew et al., 2025: eBLISS и gradient boosting, sensitivity 0.72, specificity 0.85. Из прочитанного абстракта нельзя установить достаточность независимого пользовательского/временного разделения или доступность сырых данных. Эти цифры не являются сопоставимым benchmark NutriFit. [Первичная публикация](https://pubmed.ncbi.nlm.nih.gov/40472649/).
- Goldstein et al., 2021: протокол микрорандомизированного испытания различает прогноз риска и эффект вмешательства, включая контроль без вмешательства. Это дизайн исследования, а не доказанный эффект предупреждений. [Протокол](https://pmc.ncbi.nlm.nih.gov/articles/PMC8691411/).

Доступного пригодного для обучения набора индивидуальных траекторий по этим источникам пока не подтверждено. Публикации не переводим в вымышленные обучающие строки. Запросы авторам и сбор реальных данных в текущий scope не входят.

## Метрики
Один пользователь, одно решение в день, одно определённое вечернее событие. TP: предупреждение и срыв; FP: предупреждение без срыва; FN: срыв без предупреждения.
- Recall = TP/(TP+FN): доля обнаруженных срывов.
- Precision = TP/(TP+FP): доля полезных предупреждений; при отсутствии предупреждений не определена.
- FPR = FP/(FP+TN): доля дней без срыва, когда ошибочно предупредили. Не равна 1−precision.
- FP и все предупреждения на пользовательскую неделю: соответствующий счётчик / (дни наблюдения / 7).
- Youden J = recall−FPR — дополнительный обзорный показатель, не единственный критерий победы.

Показывать абсолютные TP/FP/FN/TN, pooled и macro по пользователям, знаменатели. Missing outcome никогда не превращать в 0; показывать отдельно неизвестные исходы и предупреждения по ним. Основной синтетический анализ требует полной оценки исходов. Реальные MNAR-логи не допускаются в этот прототип как доказательство общего recall/FPR.

## Рабочие инженерные ограничения
Начальные ограничения: не более 2 предупреждений за скользящие 168 часов; macro FPR ≤15%. Это исследовательские параметры из прежнего обсуждения H19, не клинически обоснованные нормы.
Окно в реализации (t−168h, t]: ровно через 168 часов старый слот освобождается. Решения одного пользователя с одинаковым временем запрещены. Каждый исход сопоставляется ровно с одним решением.

## Единственное основное сравнение
Одинаковые замороженные вероятности tuned_scalar_v12:
1. static: фиксированный порог и жёсткий лимит 2/168h.
2. budget_aware: при двух свободных слотах базовый порог; при одном — base + reserve_penalty × remaining_fraction, где remaining_fraction — время до освобождения самого старого слота, делённое на 168h. При нуле слотов предупреждение запрещено.
Политика принимает только вероятность и время; оценочные исходы ей недоступны. Нет знания будущей недели, адаптации по evaluation-меткам или изменения p0.

## Выбор и оценка
Обязательная зависимость: исправленный replay V12 и его проверки. Использовать его dev_scores_all.json; исходные исторические результаты не перезаписывать.
dev_1 используется для настройки политики. dev_2 и dev_3 — для поисковой оценки без настройки. Эти когорты уже известны и использовались при выборе модели V12: независимым подтверждением такой результат не является.

Сетка base = 0.00, 0.05, …, 1.00, 1.01 (последний означает отсутствие предупреждений). Для budget_aware reserve_penalty = 0.05, 0.10, 0.20. Всего 22 static и 66 dynamic конфигурации, одна сетка, без расширения по результатам.
Static выбирается по наибольшему macro recall при macro FPR≤0.15; затем меньшие FPR, alerts/week, больший base.
Dynamic выбирается по macro recall при FPR≤FPR выбранного static, alerts/week≤static и pooled precision≥static; затем меньшие FPR, alerts/week, penalty, больший base. Если нет допустимого варианта или static не делает предупреждений, фиксировать отсутствие кандидата и остановиться. Все ограничения проверять после применения лимита уведомлений.

Сначала сохранять выбранные конфигурации и SHA-256 полного файла прогнозов, затем отдельной командой оценивать dev_2/dev_3. Evaluation ничего не подбирает; директории только новые. Хеш доказывает целостность, но не внешнюю пререгистрацию.

Условие перехода: средний по двум dev-сидам прирост macro recall ≥0.05 (5 процентных пунктов), положительный прирост на каждом; на каждом macro FPR≤0.15 и не выше static, предупреждений/неделю не больше static, pooled precision не ниже static. Это допуск к новому исследованию, не доказанная победа.
Парные 95% bootstrap-интервалы по пользователям внутри каждого сида (10 000 реплик, seed 20261301) для Δrecall и ΔFPR — поисковые; не выбирать политику по ним. Межсидовая неопределённость по двум сидам не оценена.
Не открывать подтверждающие сиды V12 20261211–20261215.

## Следующие итерации и остановки
- V13A: исправленный replay V12 → расчёт политики по этому протоколу. Если допуска нет, заморозить отрицательный результат; не перебирать новые пороги и seeds.
- V13B: только при допуске — отдельная пререгистрация новой подтверждающей когорты, мощности, единых критериев recall/ошибок/нагрузки и фиксированной модели; не использовать повторно V12 confirmation.
- V14: при отсутствии выигрыша политики — исследовать качество наблюдаемых сигналов: короткие самоотчёты голода/тяги/контекста и пассивные признаки. Сначала проверить доступность, временную причинность и нагрузку. По одной группе признаков; та же сильная baseline и те же метрики. Улучшение на вручную добавленном синтетическом эффекте доказывает лишь работоспособность метода, не наличие эффекта у людей.
- Реальные данные: сначала теневое предсказание и проверяемые исходы с временными метками; отдельный дизайн для селективных пропусков. Эффективность уведомлений — отдельное исследование с контрольной группой/рандомизацией, а не вывод из recall.
